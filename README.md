# LotteOn → The.Mango 주문정보 전송 확장

롯데온 주문상세 페이지에서 버튼 한 번으로 The.Mango 주문건에 정보를 옮기고
주문상태를 `배송완료`로 바꿔 저장합니다.

## 옮기는 값

| 롯데온 | → | The.Mango |
|---|---|---|
| 주문상세 URL | → | 간단메모 **2번째 칸** |
| 주문번호 | → | 상품주문번호 |
| 실결제금액 (L.POINT 제외, 숫자만) | → | 구입금액(신고금액) |
| 결제일시 (`2026.08.29`) | → | 트래킹번호 |
| — | → | 주문상태 `결제완료` → `배송완료` |

## 설치

1. Chrome 주소창에 `chrome://extensions` 입력
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** 클릭
4. `C:\Users\admin\workspace\kny\mango\order-details\extension` 폴더 선택

> 이미 설치되어 있다면 `chrome://extensions` 에서 **새로고침(⟳)** 을 누른 뒤
> 롯데온·망고 탭을 각각 새로고침해야 변경이 반영된다.

## 사용법

1. 롯데온 주문상세 페이지(`.../p/order/claim/orderDetail?odNo=...`)를 연다
2. **주문번호 옆의 🥭 망고로 전송** 버튼 클릭
3. 망고 주문관리 탭이 열려 있으면 그 목록에서 주문건을 찾고,
   없으면 수령인 이름으로 검색한 페이지를 자동으로 연다
4. 값 입력 + 주문상태 변경 + 해당 행 체크 → **선택수정**까지 자동 클릭되고
   `수정하시겠습니까?` 확인창도 자동 승인되어 **저장까지 완료**된다

## 주문건 매칭 방식

롯데온의 **받는 분** 이름으로 망고 목록에서 후보를 찾고, 아래로 점수를 매겨 1건을 고른다.

- 이미 같은 주문번호가 들어있는 행 → 즉시 선택 (재전송)
- 총 결제금액 일치 (+4) / `LOTTEON` 발주건 (+2) / 상품주문번호 비어있음 (+1) / 상태가 결제완료 (+1)
- 반품·교환·취소완료 상태 (−5), 그리고 이 상태의 행은 값을 덮어쓰지 않고 중단

동점 후보가 2건 이상이면 자동 입력하지 않고, 망고 화면에서 후보 행을 주황색으로 표시하고
**[여기에 적용]** 버튼을 띄운다.

## 안전장치

- 저장 직전 **모든 체크박스를 해제**한 뒤 대상 행만 체크한다 (선택수정이 다른 행까지 건드리는 것 방지)
- 동점 후보가 2건 이상이면 자동 입력·저장을 하지 않고 사용자에게 선택을 요구한다
- 반품/교환/취소완료 상태의 행은 값을 덮어쓰지 않고 중단한다

> 확인창 없이 바로 저장되므로 되돌리기가 없다. 매칭이 어긋나면 그대로 저장된다는 뜻이라,
> 위 세 가지가 유일한 방어선이다.

## 망고 페이지 성능

망고를 쓰는 동안 확장이 아무 부하도 주지 않도록, **망고 페이지에는 상주하는 코드가 없다.**

- `manifest.json` 의 `content_scripts` 는 롯데온 주문상세 페이지에만 걸려 있다.
  망고 목록 페이지를 열고 검색하고 스크롤하는 동안 확장 코드는 한 줄도 실행되지 않고,
  CSS 도 주입되지 않는다.
- 롯데온에서 전송 버튼을 누른 순간에만 `background.js` 가 `chrome.scripting.executeScript` 로
  `mango_main.js`(MAIN) 와 `mango.js`(ISOLATED) 를 주입하고 `__LM_MANGO__.run(payload)` 를 호출한다.
  두 스크립트 모두 자체 가드가 있어 재주입해도 한 번만 초기화된다.
- 후보 선택 UI 의 CSS 도 후보가 2건 이상일 때만 `<style>` 로 주입한다.

주입된 뒤 실제 반영 작업도 레이아웃 강제를 최소화했다.

- 행 스캔에 `innerText` 대신 `textContent` 를 쓴다 (`innerText` 는 행마다 레이아웃을 강제한다).
- `getBoundingClientRect` 를 쓰는 곳은 간단메모 칸 순서를 정하는 부분뿐이고,
  **매칭된 1개 행에서만** 호출한다.
- 체크 해제는 `input[type=checkbox]:checked` 로 이미 체크된 것만 순회한다.
- 자동 저장 경로에서는 하이라이트·스크롤을 하지 않는다 (어차피 곧바로 페이지가 갱신된다).

### confirm 자동 승인 방식

망고의 `really_all_select_modify()` 는 `confirm('수정하시겠습니까?')` 를 거친다.
콘텐츠 스크립트는 격리된 컨텍스트라 페이지의 `window.confirm` 을 바꿀 수 없으므로,
`mango_main.js` 를 `world: "MAIN"` 으로 **필요할 때 주입해** 페이지 컨텍스트에서 실행시킨다.
저장 직전 `LM_SUPPRESS_CONFIRM` 커스텀 이벤트를 쏘면 그 스크립트가 `window.confirm` 을
`() => true` 로 잠깐 바꾸고, 3초 뒤 원래대로 되돌린다. `alert` 은 건드리지 않으므로
망고가 내는 검증 오류 메시지는 그대로 보인다.

## 참고 — 확인된 제약

- 롯데온 주문상세에는 **결제 시각이 없고 날짜만** 표시된다. 시간까지 필요하면 롯데온 내부 API
  호출이 필요한데, Imperva 봇탐지에 걸릴 위험이 있어 채택하지 않았다.
- 결제수단이 여러 개(예: 네이버페이 + L.POINT)면 **`원` 단위 금액만 합산**하고 `P`(L.POINT)는 제외한다.
- 망고 목록 페이지는 `Array.prototype.find`가 정상 동작하지 않는다. 확장은 격리된 컨텍스트에서
  실행되어 영향받지 않지만, 콘솔에서 직접 스크립트를 돌릴 때는 `.filter(...)[0]`을 쓸 것.

|---|---|---|

| `mango_main.js` | 망고 (MAIN) | 전송 버튼 클릭 시에만 주입 |
